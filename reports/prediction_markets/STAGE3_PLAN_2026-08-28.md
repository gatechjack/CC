## 4. Central risk chokepoint — design
One PM-wide chokepoint every live order transits; sub-divisions produce signal+sizing intent and never call the
broker. Fixed gate order (a reject consumes no budget, burns no idempotency key): (1) **disarm check FIRST** (global
then per-sub-division; read error → disarmed); (2) **per-order notional USD cap** (not contract count); (3)
**strike-exists-exact + liquid** (never nearest; re-checked at exit); (4) **dedupe/idempotency** — deterministic UUID5
over `(sub_division, wallet, ticker, outcome, stable_signal_id)`, checked against the **durable journal** (survives
restart), Kalshi `client_order_id` as backstop; (5) **per-sub-division daily cap** (in-memory `_deployed_usd`,
UTC-reset, journal-backed — **never an audit scan**); (6) **per-account exposure cap** (anchor to real balances:
`KALSHI` $165 / `KALSHI-KAREN` $493); (7) **slippage** (within `max_slippage_cents`; fail-closed if live + no quote);
(8) **count ceiling** (trip the persistent halt — the real-time backstop the loss-halt can't be, since Kalshi P&L is
only known at settlement). One chokepoint beats per-sub-division checks because aggregate caps are only definable
where all sub-divisions are visible, there is one dedupe namespace + one kill path, and it contains the first-order
blast radius to one reviewable path. It wraps `kalshi_live.place_order` verbatim (NO-leg inversion, idempotency,
benign-nofill split, $0-preflight already there); its job is to hand that primitive gate-approved inputs.

## 5. Kill-switch / arming — design (default DECIDED: fail-safe disarmed)
Reuse the persistent `agent_state` halt row (`StrategyState.persist_halt`). A single operator action sets the
persisted disarm; the chokepoint reads it first, so the next order and all after (across restarts) are blocked. Expose
via the LIVE page (R3) AND a CLI/direct write (works if pm_web is down). **Default on restart = DISARMED (ruling #3):**
a restart is exactly when in-memory counters/high-water marks are gone; auto-resuming risks a reset daily cap or
copying history on boot; disarmed forces a human to confirm boot-reconciliation before re-arming. **Accepted cost:** an
unattended restart leaves the live lane down until Jack re-arms. Conditional auto-arm stays off the table until
boot-reconcile exists. Scope: per-sub-division + a global master kill. Auto-disarm (latching): loss threshold (fires
late), consecutive loud `OrderPlacementError`, auth failure, count ceiling, boot-reconcile mismatch. Residual: a kill
after the halt-check but before `post()` is one order wide.

## 7. Whale-exit (D1) — DECIDED: Option D, the hybrid (ruling #2)
**Ruling #2 (Jack):** exit signal = **`/activity` SELL as the trigger + `/positions` size reduction as confirmation.**
Reasoning (recorded): **bias-down, never up** — a missed exit costs one losing copy; a phantom exit dumps a real
position and can repeat. D is the phantom-averse choice and the only option that handles partials AND sold-vs-redeemed
together. **Accepted costs:** two pollers, two rate budgets, slowest. **Residual (recorded honestly):** if the two
signals never co-occur within the window, the exit is missed. The paper lane deliberately does NOT solve the live
exit (it defers vanished legs to gamma adjudication days later, `paper.py:356`) — so this is net-new for the LIVE lane.

*Options considered (kept for the record):* A `/positions` paging+confirm-vanish (blind to sold-vs-redeemed; phantom-
prone via K1); B `/activity` SELL only (best semantics, can miss/lag; needs partial handling); C size-delta (handles
partials, most noise-sensitive); **D hybrid (CHOSEN)** — highest confidence per fired order (K1 needs BOTH signals
wrong at once), best sold-vs-redeemed handling, at the cost of latency/complexity/coverage.
