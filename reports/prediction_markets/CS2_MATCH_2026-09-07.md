## The shape
- **Poly cs2** — slug `cs2-{codes}-YYYY-MM-DD[-gameN]`; title `Counter-Strike: {A} vs {B} (BOn) - {event}`;
  outcome = the org bet on. `-gameN` slug (or a `... - Map N Winner` title) = a MAP bet (out of scope).
- **Kalshi KXCS2GAME** — ticker `KXCS2GAME-{YYMONDD}{HHMM}{BLOB}-{CODE}`; title `{Org} wins`;
  `yes_sub_title` = the full org display name. The two YES tickers of a match share the middle (date, blob).
- **Join** = pair-key on the Poly title "A vs B" ↔ the Kalshi two-side market, by EXACT-normalized org names,
  within a ±1 day window (Asia-Pacific matches straddle UTC midnight — the tennis-proven construct), uniqueness-guarded.

## Why EXACT-normalized, never fuzzy (cs2's Cerundolo case)
Esports org names collide by design between a parent and its academy / women's / junior / regional / ex- roster:
`ENCE` vs `ENCE Academy`, `FURIA` vs `FURIA fe`, `MOUZ` vs `MOUZ NXT`, `G2` vs `G2 Ares`, and every `ex-<Org>`
(a disbanded lineup). These are DISTINCT ENTITIES. The only name equality is: accent-fold + lowercase + strip
punctuation + collapse whitespace, then EXACT compare (optionally through the alias table). `"ence"` ≠ `"ence academy"`.
A fuzzy (substring / first-token / prefix) match would place a real order on the wrong team — so it is never used.
(mlb/ufc/tennis are untouched; cs2 has its OWN module. tennis's fuzzy `match_fighter_name` is deliberately NOT imported.)

## Market-type gate (moneyline only)
The single rule "the outcome must EXACT-normalize to one of the two title sides" is BOTH the moneyline test and the
wrong-market-type guard. Taxonomy of all 8,802 real cs2 rows:
- 4,182 moneyline (outcome == a title side) — the copyable set
- 1,031 handicap/spread (a match title, but the outcome is `Legacy (+1.5)` / `Map Handicap: VIT (-1.5)` …) → non_moneyline skip
- 2,794 map winner (`-gameN` slug / `Map N Winner` title) → map skip
- 795 totals (`Games Total: O/U 2.5`, `Map N Total Rounds …`, odd/even) → non_moneyline skip

## Alias table — how small, how volatile
322/514 distinct moneyline title orgs join with ZERO aliases (both venues publish full display names). Built from
the REAL two-venue names (not typed): **6 same-team UNIFICATIONS** (each an exact full-string key, so academy
variants are never touched — collision-checked):

| Poly form | Kalshi form | canonical |
|---|---|---|
| `b8 esports` | `B8` / `B8 Esports` | `b8` (— `b8 academy` stays distinct) |
| `betboom team` | `BetBoom` | `betboom` |
| `themongolz` | `The Mongolz` | `the mongolz` |
| `liquid` | `Team Liquid` | `team liquid` |
| `sinners` | `SINNERS Esports` | `sinners esports` |
| `kaleido gaming` | `Kaleido` | `kaleido` |

**Volatility:** these six are STABLE renames (formal-vs-short / spacing / "Team"/"Esports" suffix — permanent).
The VOLATILE class is left as accepted safe-misses: sponsor prefixes (`BET-M 33`→`33` — sponsors change) and a
Kalshi-side encoding glitch (`Honvéd` stored with a corrupt byte → normalizes to `honv d`). A miss is acceptable.
New/small orgs appearing next season just add safe misses — never wrong picks. Regenerate the table by re-running
the dry-run when coverage shifts.

## The dry-run gate (the acceptance test)
4,182 real Poly moneyline bets vs the real KXCS2GAME index (Poly from box read-only sqlite = 0 Kalshi load; Kalshi
fetched off-box, local IP; harness `cc/cs2_dryrun.py`):
- ★ **wrong_team = 0, wrong_market_type = 0** on 1,725 real matches.
- **In-window match = 95.8% (1,725 / 1,800)** — the honest live number (Kalshi exposes only 2026-06-30..09-09;
  older Poly bets are `out_of_window` fetch artifacts, not live misses).
- In-window misses all classified SAFE: 53 one-org-absent (small orgs Kalshi doesn't list + the 2 deferred aliases),
  19 rematch within ±1d (ambiguous → safe miss), 3 both-absent.
- ★ The wrong_team check CANNOT validate an alias (a bad alias corrupts both sides consistently). Each alias was
  verified as an unambiguous same-team rename against the data — NOT inferred from a shared opponent (that yields
  false positives like "100 Thieves opp=OG" where a team merely played a common opponent in the window).
