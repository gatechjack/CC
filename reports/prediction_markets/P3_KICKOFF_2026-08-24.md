## RECONCILIATION CONTRACT (Jack adopted my three catches as spec — encode all in tests)

Each drill returns rows whose count reconciles to a NAMED `pm_category_stats` aggregate. The three non-obvious ones (a naive drill would produce a FALSE reconciliation failure):

| drill | rows queried | reconciles to | how it reconciles |
|---|---|---|---|
| `n_resolved` | `pnl_suspect=0` | `n_resolved` | row count == n_resolved |
| `avg_win_price` | `pnl_suspect=0 AND won=1` | `wins` **and** `avg_win_price` | row count == wins; `AVG(avg_price)` over rows == avg_win_price (assert BOTH) |
| `two_sided` | **ALL rows** on condition_ids with `COUNT(DISTINCT outcome_index)>1` | `n_two_sided` | **distinct condition_id count** == n_two_sided (NOT raw row count — each two-sided cid has >=2 rows) |
| `single_game` | **ALL rows**, `classify_market_shape()=='single_game'` | `n_single_game` | row count == n_single_game — **reuses the same classifier** (not stored per-row; §13A(d) market_type deferred). Coupling encoded in a test so a classifier change fails LOUDLY instead of silently desyncing the drill from the cell. |
| `data_quality` | `pnl_suspect=1` | `n_excluded` | row count == n_excluded (rows carry `suspect_reason`) |

**Key: `two_sided` and `single_game` are computed over ALL rows (structural), NOT scoreable-filtered.** `n_resolved`, `wins`, `n_excluded` are scoreable-relative (`n_resolved + n_excluded` == all rows in the slice).

Defense-in-depth: the drill panel header renders "showing N rows — reconciles with <cell> = M" and shows a visible MISMATCH banner if N != M, so a reconciliation failure is visible in prod, never silent.
