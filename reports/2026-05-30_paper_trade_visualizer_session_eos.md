can scan TradingView charts for patterns where the bitunix model
performs well vs poorly.

  paste block of `var array<…>` declarations to a text file.

## Anomalies + forks (surfaced + resolved in-session)

1. **Phase-1 validator join recipe wrong in spec.** The task brief
   said "PA validator results live in `audit_event` rows of kind
   `pa_validation_decision`, joined by `order_id`." Verified against
   prod: that payload has NO `order_id`. The `pa_validation_redeem`
   fallback covers only ~7% of bitunix paper trades. Working recipe
   (10/10 coverage in probe, adopted): same `trigger_signal` +
   `decision.ts` within 600s before `pt.ts`. Fallback when no
   matching decision: raw `trigger_signal` as the cluster tag. See
   the Phase-1 diagnostic report for full detail.

2. **Phase-2 SQL ISO-T vs space-format datetime compare.** First
   test run failed because the SQL used `datetime(?, '-N seconds')`
   for the lower window bound. That returns a space-separated
   string; comparing it `>=` against ISO-`T` `ts` values let
   outside-window rows pass (T > space lex-wise). Fixed (`15a9b8f`)
   by computing the lower bound in Python so both sides are
   ISO-`T`. Hit the existing memory
   `feedback_sqlite_iso_datetime_comparison`.

3. **Branch-pointer slip during Phase 1.** A `git status` between
   prod-sample probes confirmed I was on the visualizer branch, but
   the next commit landed on `main`. Reflog showed an intermediate
   `checkout: moving from … to main`. Recovered cleanly:
   `git branch -f visualizer <commit>` + `git reset --hard 9fd9022`
   on main + checkout. No work lost.

4. **Pine error `CE10156` after first live load.** Multi-line ternary
   in `f_result_color` at 4-space indent (function-body indent
   level) was read by Pine as four separate statements, not as a
   continuation. Fixed by collapsing to single-line. Same risk
   exists for the multi-line `indicator(…)` block at the top
   (lines 19-25) — has not raised an error so left alone; flatten
   on demand if a future Pine version tightens.
